## v2.43 更新说明

- **失败原因分级**：`aiStatusAdvice()` 把上游状态码翻成「该改哪一栏」的具体动作——`401` 提示 API Key 无效或过期、`402` 提示账户额度不足、`403` 提示令牌缺少该模型权限、`404` 提示接口地址或模型名不存在、`429` 提示限流或额度用尽、`5xx` 提示服务商异常。此前 4xx 在面板里完全静默，用户只会反复重试同一道题。
- **4xx 不再是「暂时不可用」**：`aiFailureHint()` 原本只对 429/5xx/超时给提示，其余一律返回空串。现在瞬时失败与配置失败的文案分开：前者说明重试次数，后者直接给出要修的配置项，并保留上游错误体摘要便于对照服务商文档。
- **上游错误体不再丢**：`aiHttpErrorDetail()` 取不到错误体时只保留状态码，由 `aiStatusAdvice()` 补上可执行建议（部分中转站 401/402 直接空响应）；同时失败日志把上游原文一并写进控制台，面板日志保持一句短提示不刷屏。
- **同一配置问题合并提示**：连续第 3 次因同一条建议失败时只提示一次根因，之后静默，直到结论变化才重新计数，避免整章几十道题把日志刷满。
- **「测试连接」给出可执行结论**：设置面板此前只能回一句「接口无有效返回（检查地址/Key/模型名/网络）」，现在优先显示状态码对应的具体原因（`aiLastFailureAdvice`）；「获取模型」遇到非 2xx 也走同一套建议。
- **答案格式容错**：新增 `aiStripAnswerDecorations()` 与 `aiAnswerSegment()`，在严格解析失败后剥掉 Markdown 加粗/代码块/列表符号/引号包裹、「解析 / 分析 / 说明 / 理由」分段标题，以及「选项A」「答案是 A」「是 C」这类中文修饰词；全角字母（ＡＢＣ）在 `aiNormalize()` 里统一折成半角。
- **容错不猜答案**：宽容模式只在严格模式失败后启用，且只做「剥修饰」不做「找字母」——`The answer is C`、`C or D`、`C\nActually D`、`A 选项不对\n所以答案是 C` 仍然一律判为不可作答。
- **内存回收（章节共享注册表）**：`__xxtChapterQuestionRequests` 挂在顶层窗口上，而超星切章只替换 `frame_content` iframe、顶层窗口不重建，历史章节条目会连同已卸载的 `document` 一起被长期持有。现在每次进入章节题作用域都做一次回收：`pending` 令牌超过 120 秒即清、终态令牌在所属文档已卸载或超过 30 分钟后清、章节条目数再兜一个 8 条硬顶；当前章节整体跳过，保证跨页「另一页面已完成」的去重链路不被误清。
- **内存回收（跨页答案缓存）**：原先 `aiGetCrossPageAnswer` 只在命中过期时删掉当前这一个键，其它已过期条目一直留在缓存里。现在改为全量扫过期项，写入前也会先扫一遍。
- **新增风控（antispider）识别与暂停续跑**：超星在触发风控时会把请求 302 到 `/antispiderShowVerify.ac`，回包是一张要求输入图片验证码的页面（`【9010】操作异常，请输入图片中的验证码`）。脚本现在在响应层识别这种回包，覆盖视频任务信息、视频进度上报、文档 / 图书 / 链接 / 速课 / 直播任务和章节提交。
- **不再把验证码当成任务失败**：被打断的任务保持原状态，不再进入 `failed` 终态，也不会 `stop = true` 停掉整个引擎。
- **面板内新增验证入口**：任务配置区下方出现红色提示条，「去验证」在新标签页打开真正的验证页，完成后点「已验证，继续」即可从断点重试。验证凭据由服务端按会话识别，必须在用户自己的浏览器会话内完成。
- **章节提交层面区分风控与参数错误**：`/work/validate` 或整页重定向到验证页时，报告 `平台要求输入验证码（风控）` 而不是 `无效的参数：code-1`，并回退提交锁，验证后可直接重试。
- **视频播放期间冻结进度**：风控期间视频循环既不推进计时也不上报，避免「一秒跳过几分钟」的假进度被平台清理进度。
- **跨页面答案复用**：手机章节页与桌面章节页仅在 `workId`、题号、题型、规范化题干指纹和有序选项指纹全部一致时，才会复用另一页面已完成且已核验的答案；复用后仍需在当前页面完成选中状态核验。
- **请求失败后的短暂恢复**：本页面请求失败后，会短暂等待另一页面的已核验结果；如结果到达则继续填充和核验，避免一页瞬时网络异常直接导致整章缺题。`pending` 请求仍会被严格拦截，防止并发重复请求。
- **答题节奏加随机浮动**：新增 `GLOBAL.answerJitter`（默认 4 秒），逐题等待由固定 12 秒变为 12～16 秒随机；`answerIntervalMs()` 统一提供该时长。
- **保存/提交加随机浮动**：新增 `GLOBAL.saveJitter`（默认 3 秒），桌面和手机章节页的保存、提交等待都在原有固定基数上叠加 0～3 秒随机浮动。
- **新增 Higan API 预设**：内置 `https://api.higanai.top/v1`，按 OpenAI 兼容接口调用；模型名称以账号的模型列表为准，并新增对应 `@connect` 声明。
- **模型配置与价格提示更新**：模型选择处补充 NuoAPI「国模福利分组」说明；按当前价格，国模福利分组 1 元通常可完成 5000+ 道题，普通 GPT 低价分组约 500+ 道题。实际价格、模型和额度以账户后台为准。
- **确定性不变**：随机浮动为 `[0, 上限)` 且由 `Math.random()` 驱动；`Math.random() === 0` 时与旧行为完全一致。内存回收只删除已过期、已卸载或超出硬顶的条目，不改变作答、提交与去重语义；新增两项回归用例覆盖这两条回收路径。

## 功能概览

### 任务执行

脚本在课程页识别并依次执行任务点，支持以下类型：

| 类型 | 说明 |
| --- | --- |
| `video` | 视频播放，按平台要求上报观看进度 |
| `document` | 文档 / PPT 阅读任务 |
| `work` | 章节测验、作业 |
| `book` | 图书阅读任务 |
| `hyperlink` | 外链任务 |
| `microCourse` | 速课任务 |
| `live` | 直播回放进度上报 |

调度器使用单一 500ms 入口，具备重入保护、超时回收和「只结束一次」的释放语义；未知任务与同步异常会标记失败并写入日志。任务开始前会做重复发现防护，同一任务不会并发执行。

### 学习面板

脚本在课程页接管整个页面，渲染成一个**一屏可见的左右两栏面板**（窗口宽度 < 900px 时自动堆成单列）：

```
学习通助手 · 任务配置（视频倍速 / 章节测试开关 / LLM 配置入口）
┌──────────────────────────┬───────────────────────┐
│ 课程内容 / 章节测试       │ 运行日志               │
│ （同一张卡片，自动切换）   │                       │
└──────────────────────────┴───────────────────────┘
```

标题已经并进「任务配置」的标题行，不再单独占一张卡片；两块卡片常驻显示、**左右等高**（右栏日志区自动填满剩余高度），不靠标签切换；**LLM 配置已经并进顶部「任务配置」**，点「展开设置」才展开表单（默认收起，否则 640px 的表单会把课程卡片挤出首屏）：

| 区块 | 用途 |
| --- | --- |
| 任务配置 | 视频倍速、复习模式、学习进度、章节测试四个开关；宽屏时三组（视频倍速 / 章节测试 / LLM 配置）并排一行，窄屏自动折行 |
| 课程内容 / 章节测试 | 同一张卡片：视频与阅读任务在这里正常播放/显示，进入章节测试时卡片自动切到答题页（标题追加「· 作答中」） |
| 运行日志 | 增量渲染的实时日志（保留最近 240 条），含跨 iframe 的诊断事件 |

LLM 表单在面板渲染时就已经由脚本挂进 `#llmSettingsContainer`（默认收起），点开即用，不会停在「正在加载 LLM 配置…」。考试/作业页没有主面板时改为可拖动的浮层卡片。

### 自动答题

- **选项映射**：题目选项以有序描述符表示（页面字母、题目 ID、选项 ID、DOM 节点），不会把 `{ length: 0 }` 之类的元数据混入发给模型的选项。
- **严格解析**：单选 / 多选 / 判断题只接受约定的答案格式，普通英文说明、越界字母、重复文本导致的歧义一律判为无效。
- **点击后回读**：每次点击立即回读真实选中状态；点击无效时按优先级尝试内部容器、原生控件，并兜底切换控件与 `aria-checked` / `cur`。
- **提交门禁**：只有全部题目「填充成功且回读核验通过」才允许自动保存 / 提交；零题、未处理题、题目切换、过期响应都会阻止提交。
- **跳过题也算已处理**：开启「跳过已作答」后，页面上本来就有答案的题会记成一条已处理记录（收尾时单独标注「其中 N 题沿用页面已有答案」），不会再被误报成「页面校验未通过或未作答」而卡住整章提交；如果页面上的选中状态后来被改掉，则改报「页面已有答案已失效，需重新作答」。
- **沿用答案不算「被拒后重交」**：该章节上一次提交被平台拒绝（`无效的参数：code-1！` / `不能为空` 等）时，页面上那份「已有答案」很可能就是被拒的旧答案，此时沿用它们凑出的 100% 不计入覆盖率结论，会直接提示取消勾选「跳过已作答」后重新作答，避免拿同一份答案再被拒一次。
- **提交前等在途请求**：桌面章节页只核验本页结果，看不到手机章节页还在跑的 AI 请求。提交前会遍历跨窗口共享注册表 `__xxtChapterQuestionRequests`，只要该章节还有 `pending` 令牌就继续等（每 500ms 轮询，最长 60 秒），等不到就放弃本次自动提交并提示「仍有 N 道题在途未结束」，而不是 2 秒后硬交一份答了一半的卷子。
- **提交锁可回退**：提交锁带 60 秒存活上限；命中平台拒绝文案（`无效的参数` / `code-1` / `不能为空` / `参数错误` / `提交失败`）时立即回退为可重试。已批阅（`reviewed`）是终态，不会被迟到的失败弹窗降级。
- **进入提交不打断在途结果**：章节进入 `submitting` 后只阻止**新**的题目请求，已在途请求返回的答案仍会正常写入页面——提前作废只会把答对的题当成「题目已切换，已丢弃过期答案」丢掉，反而变成缺题提交。
- **提交优先**：自动提交与自动保存同时开启时跳过保存（保存可能弹出平台提示或刷新页面导致整章重答）。
- **凭证一致性**：手机题页与桌面题页共用同一套提交锁，按课程 `workId` 防止两条流程重复提交。
- **走平台自己的提交链路**：桌面题页的提交是 `btnBlueSubmit` → `/work/validate` → `toadd`（写 `enc` 与 `answerwqbid`）→ 「确认提交？」弹窗 → `submitCheckTimes` → POST。早期版本在 `btnBlueSubmit()` 一返回就直接调 `submitCheckTimes`，跳过了 `toadd` 和确认框，表单里的凭证与待提交题号清单都是空的，服务端一律回 `无效的参数：code-1！` 并刷新整页。现在脚本接管平台的 `workPop` 确认框，**只在清单写好之后**才替你点确定；清单没写就原样留给用户，并提示「平台未进入提交流程（凭证未就绪）」。
- **拦截原因如实上报**：`/work/validate` 回 `status=1`（账号异常）或 `status=2`（验证码）时平台不会回调 `toadd`，确认框根本不会出现；脚本会报出「平台要求输入提交验证码」等真实原因，并在平台弹拒绝文案（`code-1` 等）时直接贴到面板，不再一边弹错误一边显示「已发起提交」。

### AI 请求层

- OpenAI 兼容接口，提示词固定前置以提升缓存命中率。
- 统计 AI 调用次数、缓存命中率、耗时。
- 支持 SSE / 流式响应解析（`data:`、`[DONE]`、`delta.content`）。
- 可配置**超时**、**失败重试次数**（0–5，默认 2，遇 429/5xx/超时按 0.8～1.5s 退避重试）和**并发上限**（1–6，默认 2）。
- 内置默认节奏：连接超时 5s、单次响应超时 22s、单题总等待上限 45s，超限即跳过该题。
- 运行日志可读性：每条题目/请求日志都带题型中文名、选项数、题干摘要、平台题号、来源流程（手机章节页 / 桌面章节页 / 考试页）；重试日志写明剩余机会与单题总等待上限，超时叠加后的总耗时会额外说明「单次超时 ×N 次尝试」，避免误判为参数失效；答案解析失败会附模型原文摘要；章节收尾会列出未通过的题号与原因。
- 内置模型预设（自定义 / DeepSeek / Ollama 本地 / [NuoAPI](https://nuoapi.net/register) / [Higan API](https://api.higanai.top/)），可通过 `/models` 拉取候选模型列表。
- 可选「跳过已作答题目」（默认关闭），识别 `aria-checked="true"`。命中跳过时不调用 AI，也就不再等那 12 秒逐题风控间隔（只留 120ms 让步，且不加随机浮动），已答过的题越多，一轮扫描越快。
- 逐题与保存/提交都带**随机浮动**：`GLOBAL.answerJitter`（默认 4 秒）让每题在 12 秒风控间隔之上再多等 0～4 秒；`GLOBAL.saveJitter`（默认 3 秒）让保存与提交在固定基数上再多等 0～3 秒。等间隔本身也是机器特征，浮动后每题的节奏都不相同。

### 稳定性

- 风控（antispider）可续跑：超星触发风控时会把请求 302 到 `/antispiderShowVerify.ac` 并回一张要输入图片验证码的页面。脚本在响应层识别这类回包（`antispiderShowVerify` / `processVerifyPng` / `【9010】操作异常` / `请输入图片中的验证码`），覆盖视频任务信息、视频进度上报、文档 / 图书 / 链接 / 速课 / 直播任务与章节提交。命中后**只暂停派发、保留任务状态**，不写 `failed`、不置 `stop`；面板提示条给出真正的验证页链接，用户验证完点「已验证，继续」即从断点重试。验证期间视频循环冻结计时与上报，避免假进度被平台清理。
- 单实例运行：通过心跳租约（`__xxtAssistantLease`，TTL 30s）保证同一顶层窗口只有一个执行者，过期自动让位。
- 同账号多窗口：`xxtStudySessions:<uid>` 会话表（10 分钟 TTL）检测并提示「另一窗口正在学习不同课程」。
- 图片 / 听力题文本化：自研纯字符串分词器，不依赖 DOM 与 `innerHTML`，过滤 `javascript:` / `data:` / `blob:` 等来源。

## 安装

1. 安装脚本管理器（任选其一）：
   - [Tampermonkey](https://www.tampermonkey.net/)
   - [Violentmonkey](https://violentmonkey.github.io/)
   - [ScriptCat](https://scriptcat.org/)
2. 二选一完成安装：
   - **在线安装（推荐）**：打开 [脚本猫脚本页](https://scriptcat.org/zh-CN/script-show-page/8922)，点「安装此脚本」，版本更新由脚本管理器自动处理；
   - **手动安装**：新建用户脚本，粘贴 [超星学习通助手.user.js](./超星学习通助手.user.js) 的全部内容并保存，但这样收不到自动更新。
3. 打开超星学习通课程页，脚本 `@run-at document-end` 自动注入。

源码与历史版本都在 <https://github.com/hjm-al/chaoxing-assistant>，遇到问题请提到 [Issues](https://github.com/hjm-al/chaoxing-assistant/issues)。

脚本需要以下 GM API：`GM_xmlhttpRequest`、`GM_setValue`、`GM_getValue`、`GM_info`、`GM_getResourceText`、`unsafeWindow`。若脚本管理器未授权 `GM_xmlhttpRequest` 的跨域请求，AI 功能会失败。

匹配站点见文件头 `@match`：`*.chaoxing.com`、`*.edu.cn`、`*.nbdlib.cn`、`*.hnsyu.net`、`*.ac.cn`。新增站点需要在元数据块中补充 `@connect`。

已在元数据中声明 `@compatible firefox`、`@compatible chrome`、`@compatible edge`。脚本通过 `GM_xmlhttpRequest` 发起跨域请求，因此不受浏览器 CORS 限制，但需要脚本管理器授予相应权限。

装好之后每个按钮具体怎么用，见 [使用教程.md](./使用教程.md)。

## 配置 LLM

> 首次安装、还没填过接口地址时 AI 默认处于**关闭**状态（无 `ai_url` 且未保存过 `ai_mode`，按 `off` 处理）。任务可以正常执行视频、文档、图书、外链、速课与直播，但章节测验 / 作业不会自动作答，直到「LLM 配置」里填好接口地址与 API Key。**填入地址和 Key 后点保存会自动开启 AI**（提示 `已保存并启用：…`），不必再单独去改模式下拉框。

打开面板顶部「任务配置」里的「LLM 配置 → 展开设置」（考试/作业页没有主面板时，悬浮面板里的「LLM 设置」会打开一张同样内容的浮层卡片）：

| 项目 | 说明 |
| --- | --- |
| 模式 | `关闭（只做视频/文档任务）` / `开启 AI 直连答题`；凭据有变化时保存会自动切到开启 |
| 接口地址 | 形如 `https://api.deepseek.com` 的 OpenAI 兼容 base URL |
| API Key | 仅保存在脚本管理器的存储中，不写入源码 |
| 模型 | 可从候选列表选择，或点击获取模型列表后填写 |
| 超时 / 温度 | 超时最低 3000ms，默认 22000ms（正常一次 5～12s，慢请求留足余量，避免恰好卡在超时线上反复重试） |
| max_tokens | 单次回复上限，默认 1024 |
| 失败重试 | 0–5 次，默认 2 次（间隔 0.8～1.5s） |
| 并发上限 | 1–6，默认 2；数值越高越容易触发上游 429/502 |
| 提示词 | system / user 模板，固定前置有利于缓存命中 |
| 跳过已作答 | 默认关闭 | 命中时不调用 AI，也不再等 12 秒逐题间隔（该路径不加随机浮动） |
| 高级 | `headers_json`、`body_json`、`response_path` 等自定义字段映射 |

单题等待节奏（默认值，可在「LLM 配置」里用「恢复默认」一键回填）：

| 环节 | 默认值 | 说明 |
| --- | --- | --- |
| 连接超时 | 5s | 断网时快速失败；在线但响应慢会继续等满单次超时 |
| 单次响应超时 | 22000ms | 正常请求 5～12s 返回；22s 用于兜住偶发的慢响应 |
| 失败重试 | 2 次（共 3 次尝试） | 遇 429 / 5xx / 超时退避重试 |
| 重试间隔 | 0.8～1.5s | 首次约 0.8～1.0s，第二次约 1.2～1.5s |
| 单题总等待上限 | 45s | 超出即跳过该题并写入日志，避免拖死整场 |
| 并发上限 | 2 | 接口不稳定时不要调高 |

内置预设：自定义、DeepSeek、Ollama 本地、[NuoAPI](https://nuoapi.net/register)、[Higan API](https://api.higanai.top/)。其他 OpenAI 兼容服务商可选用「自定义」并填写接口地址与模型名。[Higan API v1 接口](https://api.higanai.top/v1) 的模型名以账号可用模型列表为准。

保存后配置写入 GM 存储（`ai_url`、`ai_key`、`ai_model`、`ai_timeout`、`ai_retries`、`ai_concurrency`、`ai_temperature`、`ai_max_tokens`、`ai_system_prompt`、`ai_user_prompt`、`ai_headers_json`、`ai_body_json`、`ai_response_path`、`ai_skip_answered`）。

设置页底部的「配置备份」可把这些项**导出为 JSON** 或**从 JSON 导入**（白名单写入，多出来的键被忽略），用于换设备、备份以及跨 `@storageName` 版本迁移。

## 网络请求与隐私

脚本除课程平台自身的请求外，还会发起以下几类外部请求，使用前请知悉：

| 请求 | 目标 | 频率 | 内容 |
| --- | --- | --- | --- |
| 依赖库下载 | `lib.baomitu.com`（jQuery / Vue / Element UI / axios 等）、`forestpolice.org` | 安装或首次运行时由脚本管理器缓存 | `@require` / `@resource` 声明的第三方前端库与字体表，不含个人数据 |
| 登录态与用户信息 | `passport2-api.chaoxing.com` | 页面加载时 | 平台自身的登录态校验，与浏览器已登录会话一致 |
| 直播回放进度上报 | `zhibo.chaoxing.com` | 直播回放任务进行中按间隔上报 | 课程号、用户 ID、直播流标识与观看进度，与网页端行为一致 |
| AI 答题 / 问答 | 你在「LLM 配置」中填写的接口 | 每次答题 | 题干、选项、题型与提示词 |

- API Key 只保存在脚本管理器的 GM 存储中，不写入源码，也不会随脚本分发；但会作为请求头发送给**你自己配置的** AI 服务商，请自行评估其隐私政策。
- 「LLM 配置」页底的**配置备份**（导出 / 导入）在你本地点按钮时读写同一份 GM 存储，只把 JSON 写进页面文本框，不发起任何网络请求；导出的文本含 API Key 明文，自行保存时请注意。
- 脚本不读取其它 GM 存储命名空间（GM 接口也不允许），因此更换 `@storageName` 后旧配置无法自动迁移，只能由用户导出 / 导入或重填一次。
- 图片题不走任何外部 OCR 服务：脚本直接解析题面 DOM 文本，不会把图片上传到第三方。
- 脚本不含任何统计、埋点或广告下发；面板顶部不再有图片位，界面宽度由面板自身决定。
- 文件头 `@connect` 逐条都有代码对应，`*` 仅用于你在「LLM 设置」里自填的任意 OpenAI 兼容接口；`pan-yz.chaoxing.com` 只用于图标与日志截图，不发起接口请求。

### 商业关联披露

脚本**不含**任何推广参数、返利链接或分成关系。面板「获取密钥」行与「未配置」时的失败提示里给出的是 NuoAPI 的普通注册地址：

```
https://nuoapi.net/register
```

该地址不带 `aff`、`ref`、`utm` 等任何追踪参数，作者也不会因此获得任何形式的分成或返利。它是「选哪家服务商」的默认示例之一，与 DeepSeek、Ollama 本地预设地位相同。

它不影响脚本任何行为：接口地址、模型、Key 都可自由填写，选「自定义」接任意 OpenAI 兼容服务，或用「Ollama 本地」跑本地模型，功能完全一致。链接也不会被短链、跳转页包装或静默改写——测试 `the NuoAPI entry is a plain link with no tracking parameter` 会守住这条边界。

历史上元数据曾声明 `@antifeature referral-link`，随推广参数一并移除；`@antifeature payment` 保留，它如实说明 AI 答题依赖第三方付费接口。

## 界面模板（`XXT_UI` 模块）

脚本中所有 HTML/CSS 模板都集中在主文件顶部的 `XXT_UI` 模块里（`var XXT_UI = (function () { ... })()`，以 `// ==================== UI 模块结束` 收尾），不再散落在各处：

| 成员 | 对应界面 |
| --- | --- |
| `TOKENS` | 三套界面共用的 CSS 设计令牌（`:root` 变量） |
| `PANEL_HTML` / `panelHtml(opts)` | 考试/作业页可拖动悬浮面板（答案表格 + 状态行 + 操作按钮） |
| `PAGE_HTML` / `pageHtml(opts)` | 学习通主页面注入的两栏面板结构（无标签页，课程内容与章节测试共用一张卡片，LLM 配置并进顶部「任务配置」） |
| `SETTINGS_HTML` / `settingsHtml()` | LLM 配置面板（`aiSettingHtml()` 的模板来源） |

模板内的动态取值统一用 `__XXT_*__` 占位符标记，由 `fill()` 在调用时替换；文本类内容走 `escapeText()` 转义后再插入。`aiSettingHtml()`、`showPanel()` 等原有函数名保持不变，只是改为调用模块，因此调试页生成脚本与浏览器夹具的切片边界依然有效。

测试直接从生产脚本中提取函数运行，覆盖答案解析、选项映射、点击回读、请求归属、提交门禁、任务状态、调度器单计时器、媒体解析、单实例租约、视频进度加密串、`replaceAll` 兜底，以及「题库比对」「版本检查」「旧非 AI 答题路径与智慧树残留」三条已删除链路不得回潮的守护断言，和「推广链接参数不得被截断或换成短链」的商业边界断言等场景。请求归属相关的用例还专门守护了新版考试页的行为：`input[name^=answer]` 缺失或重名导致多道题共用同一 key 时，已完成的记录不得把后面的题目挡成「已有处理请求」。

章节提交协调层另有独立用例：提交锁在 `failed`／超时后必须放行重试、`reviewed` 终态不得被迟到的失败弹窗降级、`submitting` 在有效期内必须继续挡住另一页面；以及 `aiWaitChapterPendingRequests` 只在共享注册表清空（或超出预算）时才返回。

长会话内存回收另有三条用例：章节共享注册表要能清掉已卸载文档与超期章节、但绝不能清掉当前章节（它还要参与跨页去重）；跨页答案缓存一次写入要清掉所有过期条目（而不是只清查到的那一条）；读取路径的清扫必须节流，写入路径必须强制清扫。

## 已知限制

- 真实课程页的手机 / 桌面章节题页、平台保存与提交返回结果**尚未验证**；现有结论来自 Node 回归与 Edge 夹具。
- 未采集真实运行中的 CPU、内存、网络请求基线，因此**不宣称任何性能提升**。
- 提交前的在途请求等待依赖两个题页共享 `window.__xxtChapterQuestionRequests`：如果用户只在其中一个页面开了脚本、另一个页面是纯手工操作，脚本无法感知手工操作，仍可能提交到「另一页刚手动改过」的状态。
- 平台 DOM 结构随版本变化，选项定位、点击目标与选中态读取均做了多级兜底，但仍可能因改版失效。
- SSE、`response_path` 等能力依赖具体模型服务的返回格式，不同供应商可能需要调整高级配置。
- 「作答覆盖率」表示成功填充并核验通过的比例，**不等于平台判定的正确率**。
